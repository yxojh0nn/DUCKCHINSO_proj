# 아티스트 프로필 · 검색 세분화 · Apple Music 연동 기획

작성일: 2026-11-10 · 상태: **기획 (Apple 개발자 프로그램 가입 후 착수)**
범위: ① 아티스트별 프로필 화면 ② 캘린더 검색을 "공연 / 아티스트"로 분리 ③ Apple Music API 사용 가능 범위와 연동 방식

> 약관 정리는 2026-11-10에 공식 문서를 읽고 요약한 것이다. 법률 자문이 아니며, 착수 전에 원문이 바뀌지 않았는지 다시 확인한다. 원문을 옮겨 적지 않고 조항 번호와 요지만 적는다.

---

## 1. 결론 요약

| 질문 | 답 |
| --- | --- |
| 개발자 프로그램에 가입하면 Apple Music API를 쓸 수 있나 | **쓸 수 있다**(추가 비용 없음). 단 **용도 제한이 크다** |
| 아티스트 프로필에 Apple Music의 사진·소개·대표곡을 가져다 보여 줘도 되나 | **MusicKit(Apple Music API)으로는 안 된다.** 약관이 "구독 이용과 무관한 목적"과 "재생과 떨어진 앨범 아트·텍스트 사용"을 금지한다 (3장) |
| 그럼 어떻게 | ① 이미지·정보 없이도 되는 프로필을 먼저 만들고 ② "Apple Music에서 듣기" **링크(배지)** 만 붙인다 ③ 홍보용 표시가 허용되는 **Apple Music Feed** 사용 가능 여부를 Apple에 확인한 뒤 이미지·미리듣기를 붙인다 |
| 아티스트 목록 자체 | 지금처럼 **MusicBrainz(CC0)** 로 수집한다 (Apple 데이터로 목록을 만들지 않는다) |

## 2. 기능 기획

### 2-1. 캘린더 검색 분리 (`/search`)

```
[←] [ 검색어                         (x) ]
     공연 | 아티스트          ← 탭 (마지막 선택 기억)
```

| 탭 | 검색 대상 | 결과 | 비고 |
| --- | --- | --- | --- |
| **공연** (기본) | 공연명·공연장·지역·출연 아티스트명 | 지금과 같은 공연 목록 + 장르·가격·날짜·관심 공연 칩 | 현재 `Search.tsx` 그대로 |
| **아티스트** | 한국어·일본어·영문 이름 + 별칭 | 아티스트 목록 (이름, 다른 표기, 다가오는 공연 수) → 누르면 프로필 | 검색어가 없으면 **다가오는 공연이 있는 아티스트 먼저**, 그다음 가나다순. 50명씩 이어 불러오기(`LoadMore`) |

- 아티스트 검색은 이미 받아 둔 전체 목록(`useArtists`, 827명)에서 브라우저 안에서 찾는다. 서버 요청 없음
  - 1만 명을 넘기면 서버 검색(`ilike` + 쪽 나눔)으로 바꾼다
- 별칭 검색을 위해 `listArtists`가 `aliases`도 받게 한다 (지금은 운영자 화면만 받음)
- 공연 탭의 결과에서 출연 아티스트 이름을 누르면 아티스트 탭이 아니라 바로 프로필로 간다

### 2-2. 아티스트 프로필 (`/artist/:id`)

```
┌─────────────────────────────┐
│ [이미지 또는 이니셜 원]       │  ← 1단계: 이니셜 + 아티스트 색 / 3단계: 허용된 이미지
│ YOASOBI                      │
│ ヨアソビ · YOASOBI           │  ← 다른 표기
│ ♥ 관심 아티스트   덕친 128명  │  ← 담기·해제(최대 5명 규칙 유지), 좋아하는 회원 수
├─────────────────────────────┤
│ 다가오는 공연 (2)            │  ← ConcertRow 재사용, 공연 상세로
│ 지난 공연 (보관 기간 안)      │
├─────────────────────────────┤
│ 관련 커뮤니티 글             │  ← 2단계: 공연 후기 글(해당 공연) 최신 5개
├─────────────────────────────┤
│ [Listen on Apple Music 배지] │  ← 링크만 (4-1)
│ 정보 출처: MusicBrainz(CC0)… │
└─────────────────────────────┘
```

| 항목 | 데이터 | 단계 |
| --- | --- | --- |
| 이름·다른 표기 | `artists.name / name_ja / name_en` | 1 |
| 관심 아티스트 담기 | `user_artists` (기존 규칙: 최대 5명) | 1 |
| 좋아하는 회원 수 | 새 DB 함수 `artist_fan_count(id)` (숫자만, 누가인지는 비공개) | 1 |
| 다가오는 공연·지난 공연 | `concert_artists` → `concerts` (기존 데이터) | 1 |
| Apple Music 링크 배지 | Apple Music 검색 주소 또는 아티스트 주소 (4-1) | 1 |
| 관련 커뮤니티 글 | `posts.concert_id`가 이 아티스트 공연인 글 | 2 |
| 이미지·대표곡·미리듣기 | **Apple Music Feed 승인 시에만** (4-3) | 3 |

진입 경로: 검색(아티스트 탭) · 공연 상세의 출연 아티스트 이름 · MY > 관심 아티스트 목록 · 덕친 프로필의 관심 아티스트

### 2-3. 운영자

- 아티스트 편집 화면에 `Apple Music 아티스트 ID`(선택) 칸 추가 → 넣으면 배지가 검색 주소 대신 아티스트 페이지로 바로 간다
- 이미지 칸은 3단계 전까지 두지 않는다 (출처가 불분명한 이미지를 운영자가 올리는 것을 막기 위해)

## 4. 구현 방식

### 4-1. 1단계: Apple Music 링크만 (API 호출 없음, 약관 위험 최소)

- 배지 링크 주소
  - 운영자가 Apple Music 아티스트 ID를 넣은 경우: `https://music.apple.com/kr/artist/{id}`
  - 없으면: `https://music.apple.com/kr/search?term={일본어 또는 영문 이름}`
- API를 부르지 않으므로 3.3.6(D)의 "무관한 목적 호출"에 해당하지 않는다. Identity Guidelines(배지 원본·위치·링크)만 지킨다
- 배지 SVG는 Apple 마케팅 도구(Identity Guidelines 페이지의 다운로드)에서 받아 `public/badges/`에 둔다. 한국어 배지가 있으면 그것을 쓴다
- 처리방침·약관 화면 하단에 상표 문구 추가

### 4-2. 개발자 토큰 (3단계·재생 기능용, 필요할 때만)

- Apple Developer → Identifiers → **Media IDs**로 MusicKit 식별자 생성 → Keys에서 MusicKit 키 생성, `.p8`(한 번만 받을 수 있음)과 Key ID 보관
- 서버 함수에서 ES256 JWT 생성: 헤더 `alg=ES256`, `kid=Key ID` / 클레임 `iss=Team ID`, `iat`, `exp`(**최대 약 6개월**). 요청은 `Authorization: Bearer <토큰>`
  - 상세 값(최대 수명, 웹용 `origin` 클레임)은 공식 문서에서 다시 확인한다 (이번 조사에서 문서 본문을 읽지 못함)
- 비밀값: `APPLE_TEAM_ID`, `APPLE_MUSIC_KEY_ID`, `APPLE_MUSIC_PRIVATE_KEY`(p8 내용) → `supabase secrets set`. 앱 번들·저장소에 넣지 않는다
- 토큰을 앱에 내려줄 때는 짧게 캐시하고, 키는 서버 밖으로 나가지 않는다

### 4-3. 3단계: 이미지·미리듣기 (Apple Music Feed 확인 후)

1. **접근 조건 확인 (사용자):** Apple Music Feed가 개발자 프로그램 회원에게 바로 열리는지, 별도 신청·승인이 필요한지 Apple Developer 문서·지원에 확인한다
   - 문서 페이지: https://developer.apple.com/documentation/applemusicfeed
   - 이번 조사에서 본문을 읽지 못했다
2. 승인되면 프로필 화면을 3.3.6(F) 조건에 맞춘다
   - 이미지·미리듣기를 **배지(그 아티스트의 Apple Music 페이지 링크) 바로 옆**에 둔다
   - 미리듣기에 "provided courtesy of Apple Music" 표기
   - 이미지·미리듣기를 **우리 저장소에 복사하지 않고** Apple 주소를 그대로 쓴다. 저장·캐시·가공 금지라서 포스터처럼 썸네일 변환도 하지 않는다
   - 프로필 외 화면(목록 아이콘, 덕친 프로필 등)에는 쓰지 않는다
3. 승인되지 않으면 이미지는 **이니셜 원**을 유지한다. 대안으로 Wikimedia Commons의 자유 라이선스 사진이 있다(저작자·라이선스 표기 필수). 다만 J-pop 아티스트는 사진이 없는 경우가 많아 우선순위가 낮다

### 4-4. 하지 않을 것

- Apple Music API로 아티스트 검색·사진·소개를 받아 우리 DB에 쌓기 (2.6, 3.3.6(D) 위반)
- Apple Music 데이터를 유료 기능·광고와 엮기 (3.3.6(D) 간접 수익화)
- 인터넷에서 찾은 아티스트 사진을 운영자가 올리기 (저작권·초상권)

## 7. 확인하지 못한 것

- Apple Music Feed의 접근 자격(전체 회원 / 신청 승인)과 제공 데이터 범위 (문서 본문 미확인)
- 개발자 토큰 최대 수명·웹 `origin` 클레임의 정확한 값 (문서 본문 미확인, 기억에 의존)
- 라이선스 계약 2.8의 "Apple 기기에서만 사용" 문구가 웹·Android의 배지 링크에도 영향이 있는지. 링크는 서비스 이용이 아니라서 해당하지 않는다고 보지만, Feed·API를 Android·웹에서 쓸 경우에는 확인이 필요하다
- 계약서 최종 갱신일 (가져온 본문에서 찾지 못함)

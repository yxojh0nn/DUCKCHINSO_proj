# 덕친소 배포 가이드 (웹 → Android·iOS)

작성일: 2026-11-03

코드는 하나다. 같은 `dist` 빌드를 Vercel(웹)에 올리고, Capacitor로 Android·iOS 앱에 넣는다.

- `VITE_SUPABASE_URL`·`VITE_SUPABASE_ANON_KEY`가 없으면 **데모 모드**로 돈다. 브라우저 localStorage만 쓰고, 가상 사용자가 자동으로 답장한다.
- 값을 넣으면 실제 백엔드(Supabase)로 동작한다.

아래 단계에서 계정 가입·로그인·키 발급은 **직접** 해야 한다.

## 1. 로컬 실행

```bash
pnpm install
```
```bash
pnpm dev
```
```bash
pnpm test
```

`pnpm test`는 캘린더 표시 계산, KOPIS 파싱, DB 스키마(권한·탈퇴 범위)를 검사한다.

## 2. Supabase 프로젝트

1. supabase.com에서 프로젝트를 만든다. 지역은 Northeast Asia (Seoul).
2. 이 저장소를 프로젝트에 연결하고 마이그레이션을 올린다.
```bash
npx supabase login
```
```bash
npx supabase link --project-ref <프로젝트 ref>
```
```bash
npx supabase db push
```
   - **2026-11-04 진행 상황:** 프로젝트 `DuckChinSo`(ref `alqboduujyjypvskjlha`)에 마이그레이션 4개를 대시보드 SQL Editor로 적용했다. 그래서 CLI로 연결한 뒤에는 `db push` 전에 아래 명령으로 "이미 적용됨"을 한 번 기록해야 같은 SQL이 두 번 실행되지 않는다.
```bash
npx supabase migration repair --status applied 20261103000001 20261103000002 20261103000003 20261104000004
```
   - 새 Supabase 프로젝트는 `anon`·`authenticated` 역할에 표 권한을 자동으로 주지 않는다. `20261104000004_grants.sql`이 정책에 맞는 권한만 준다. 이게 없으면 앱의 모든 요청이 403(permission denied)으로 막힌다.
3. Authentication > Sign In / Providers 설정 (2026-11-04: 비회원 켜기, 이메일 확인 켜기, Site URL `http://localhost:5173`, Redirect URL 2개 등록 완료)
   - **Anonymous sign-ins: 켜기** (비회원)
   - Email: 켜기, Confirm email 켜기
   - Google·Apple: 각 개발자 콘솔에서 클라이언트 ID·비밀값을 받아 Supabase 제공자에 입력한다. Apple은 iOS에서 소셜 로그인을 넣으면 필수다.
   - **Kakao·Naver는 Supabase 제공자를 켜지 않는다.** 서버 함수 `social-login`이 직접 처리한다(아래 3장, `docs/로그인_계정_암호화_설계.md` 4장).
4. Authentication > URL Configuration > Redirect URLs에 아래 두 주소를 추가한다.
   - `https://<웹 도메인>/auth/callback`
   - `com.duckchinso.app://auth/callback` (앱)
5. 운영자 계정 만들기 (아래 '운영자 계정' 참고)

## 3. Edge Functions·정기 작업

```bash
npx supabase functions deploy delete-account
```
```bash
npx supabase functions deploy answer-inquiry
```
```bash
npx supabase functions deploy import-concert
```
```bash
npx supabase functions deploy sync-concerts --no-verify-jwt
```
```bash
npx supabase functions deploy social-login --no-verify-jwt
```
```bash
npx supabase functions deploy login-id --no-verify-jwt
```
```bash
npx supabase functions deploy sync-artists --no-verify-jwt
```
```bash
npx supabase secrets set KOPIS_API_KEY=<키> RESEND_API_KEY=<키> MAIL_FROM="덕친소 <noreply@도메인>" MUSICBRAINZ_USER_AGENT="Duckchinso/0.1 ( 연락처 )"
```

- `sync-*` 함수는 직접 service role 키를 확인하므로 JWT 검증을 끈다.
- `social-login`은 브라우저가 직접 열고, `login-id`는 로그인 전에 부르므로 JWT 검증을 끈다(로그인이 필요한 동작은 함수 안에서 JWT를 확인한다).
- 로그인·암호화 비밀값 (값은 사용자가 직접 넣는다. 채팅·저장소에 붙여 넣지 않는다):
  - `PII_ENC_KEY`, `PII_HMAC_KEY`, `LOGIN_STATE_KEY`: 각각 `openssl rand -base64 32`로 만든 서로 다른 값. **비밀번호 관리자에 백업한다. 잃으면 아이디·연동 정보를 복구할 수 없다**
  - `SITE_ORIGINS`: 네이버·카카오 로그인 후 돌아갈 웹 주소 목록. 예: `https://<웹 도메인>,http://localhost:5173`
  - `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`: 네이버 개발자센터 > 애플리케이션 등록 (네아로). 이메일 주소 제공을 **필수**로, Callback URL에 `https://<ref>.supabase.co/functions/v1/social-login`
  - `KAKAO_REST_KEY`(REST API 키), `KAKAO_CLIENT_SECRET`(콘솔에서 켰을 때만), `KAKAO_ADMIN_KEY`(탈퇴 연결 끊기): Kakao Developers > 카카오 로그인 켜기, Redirect URI에 같은 주소. 동의 항목은 닉네임 없이도 된다(회원번호만 쓴다)
- **Vault 의 `service_role_key` 에는 legacy `service_role` 키(eyJ…)를 넣는다.** 바로 위의 `anon` 키와 헷갈리기 쉽다. 새 키 체계 프로젝트는 함수 환경의 키가 문자열로 달라서, 함수가 그 키로 관리자 API 를 한 번 불러 서버 키인지 확인한다(`_shared/supabase.ts`). legacy 키는 2027년 초 폐지 예정이라 그 전에 새 secret 키로 바꿔야 한다.
- 함수 배포는 Docker 없이 `--use-api` 로 한다. 예: `npx supabase functions deploy sync-concerts --use-api --no-verify-jwt`
- 공연 수집은 한 번에 목록 3쪽(300건)씩 `?from=1`, `?from=4`, `?from=7` 세 번 부른다. 한 번에 700건을 받으면 KOPIS 연속 요청 차단과 재시도 때문에 함수 실행 한도(150초)를 넘는다. 정기 작업은 `20261104000005_split_concert_sync.sql` 이 세 개로 나눈다.
- 정기 작업(`20261103000003_jobs.sql`)이 함수를 부르려면 SQL Editor에서 Vault에 두 값을 한 번 넣는다.
```sql
select vault.create_secret('https://<ref>.supabase.co', 'project_url');
select vault.create_secret('<service_role 키>', 'service_role_key');
```
- 첫 데이터는 손으로 한 번 실행한다. 아티스트를 먼저 받아야 공연과 대조할 수 있다.
```bash
curl -X POST -H "Authorization: Bearer <service_role 키>" https://<ref>.supabase.co/functions/v1/sync-artists
```
```bash
curl -X POST -H "Authorization: Bearer <service_role 키>" https://<ref>.supabase.co/functions/v1/sync-concerts
```
- 검수 대기 공연(`status = 'review'`)은 Supabase Studio에서 확인해 `published`로 바꾼다. 예매 오픈 일시(`ticket_open_at`)도 이때 입력한다.
- 문의 답변: 운영자 계정으로 `answer-inquiry` 함수를 호출한다(`{ inquiryId, answer }`). 관리자 화면은 2차.

## 3-1. 운영자 계정과 운영자 화면

운영자 화면(MY > 운영자)에서 검수 대기 공연 게시·숨김, 공연 찾기(수집 목록 전체에서 가져오기), 아티스트 별칭 관리를 한다.

1. 앱에서 **회원 로그인 > 이메일로 가입**으로 운영 전용 계정을 만든다. 비회원(익명) 계정은 운영자로 쓰지 않는다.
2. 받은 인증 메일의 링크를 눌러 가입을 끝낸다.
3. SQL Editor에서 그 이메일을 운영자로 지정한다.
```sql
insert into public.admins (user_id)
select id from auth.users where email = '<운영자 이메일>' and not is_anonymous;
```
4. 앱을 새로고침하면 MY 메뉴에 "운영자"가 생긴다.

- 운영자 확인: `select u.email from public.admins a join auth.users u on u.id = a.user_id;`
- 운영자 해제: `delete from public.admins where user_id = (select id from auth.users where email = '<이메일>');`
- 운영자 권한은 DB(RLS·`is_admin()`)가 확인한다. 화면의 메뉴는 보여 주기만 한다.
- 운영 계정은 사람마다 따로 만들고 공유하지 않는다. 비밀번호는 길게(12자 이상) 쓴다.

**운영 흐름**
- 검수 대기: 자동 판별 근거(점수·내한·출연진·기획사)를 보고 아티스트를 연결해 게시하거나 숨긴다. 게시하면 그 기획사가 `jpop_promoters`에 쌓여 다음 수집부터 판별 근거가 된다. 숨긴 공연은 다시 나타나지 않는다.
- 공연 찾기: 자동 판별에서 후보에도 못 오른 공연(아티스트 목록에 없는 경우)을 공연명으로 검색해 가져온다(`import-concert` 함수). 가져온 공연은 검수 대기로 들어간다.
- 아티스트: 별칭(예: 레갈릴리, Regal Lily)을 넣으면 다음 수집부터 자동으로 맞는다. 운영자가 고친 아티스트(`source=admin`)는 MusicBrainz 수집이 덮어쓰지 않는다.
- 신고: 원문(신고 시점에 서버가 복사한 내용)을 보고 **조치 완료**(글 숨김·댓글 삭제·채팅 가리기를 함께 할 수 있음) 또는 **기각**한다. 같은 내용에 들어온 다른 신고도 함께 닫힌다. 작성자에게 경고·7일·30일·영구 제한을 줄 수 있고, 당사자에게 운영팀 대화방으로 사유를 알린다. 기간 제한은 정기 작업이 끝난 뒤 자동으로 푼다. 영구 제한은 SQL로만 푼다: `update public.profiles set status = 'active' where id = '<사용자 id>';`
- 문의: 설문·본문을 보고 답변하면 사용자의 운영팀 대화방으로 간다. `RESEND_API_KEY`·`MAIL_FROM`을 함수 비밀값으로 등록하면 회원에게 메일 알림도 간다.
- 운영자 함수(`admin_reports`, `admin_resolve_report`, `admin_sanction`, `admin_inquiries`)는 함수 안에서 운영자인지 다시 확인한다.

## 5. 앱 패키징

> 스토어 출시까지의 전체 계획(막는 것, 계정, 심사 준비, 순서, 비용)은 [앱_배포_계획.md](앱_배포_계획.md)에 있다. 여기는 빌드 명령만 둔다.

공통: 웹 코드를 바꿀 때마다 아래 명령으로 빌드해서 네이티브 프로젝트에 복사한다.

```bash
pnpm cap:sync
```

`.env`에 Supabase 값을 넣고 빌드해야 앱이 실제 백엔드를 쓴다.

**Android** (`android/`, minSdk 26 = Android 8.0, target 36)

- **JDK 21이 필요하다.** 지금 PC에는 Java 26만 있어 Gradle 8.14가 실행되지 않는다("Unsupported class file major version 70").
  - Android Studio를 설치하면 JDK 21이 함께 온다. `JAVA_HOME`을 그 경로로 바꾼다.
- Android Studio로 `android/` 폴더를 열고 Run. 또는 아래 명령으로 빌드한다.
```bash
npx cap open android
```
- 스토어 배포: Build > Generate Signed App Bundle(.aab). 서명 키는 커밋하지 않는다(`.gitignore`).

**iOS** (`ios/`, 최소 iOS 16, Swift Package Manager)

- Windows에서는 빌드할 수 없다. Codemagic(클라우드 macOS)이나 Mac + Xcode가 필요하다.
- Codemagic: 저장소를 연결하고 Capacitor 템플릿을 고른 뒤, 빌드 전 스크립트에 `pnpm install && pnpm cap:sync`를 넣는다. Apple Developer 계정의 인증서·프로비저닝을 연결한다.
- 사진 접근 문구(`NSPhotoLibraryUsageDescription`), 카메라 문구, 로그인 복귀 스킴(`com.duckchinso.app`)은 `Info.plist`에 넣어 두었다.

**앱 ID:** `com.duckchinso.app`은 임시값이다(기획서 미결 사항). 바꾸려면 다음 세 곳을 함께 바꾼다.

- `capacitor.config.ts`
- `src/lib/supabase.ts`의 `APP_SCHEME`
- 네이티브 설정: AndroidManifest의 intent-filter, Info.plist의 URL scheme

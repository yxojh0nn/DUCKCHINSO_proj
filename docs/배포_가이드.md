# 덕친소 배포 가이드 (웹 → Android·iOS)

작성일: 2026-11-03

코드는 하나다. 같은 `dist` 빌드를 Vercel(웹)에 올리고, Capacitor로 Android·iOS 앱에 넣는다.

- `VITE_SUPABASE_URL`·`VITE_SUPABASE_ANON_KEY`가 없으면 **데모 모드**로 돈다. 브라우저 localStorage만 쓰고, 가상 사용자가 자동으로 답장한다.
- 값을 넣으면 실제 백엔드(Supabase)로 동작한다.

아래 단계에서 계정 가입·로그인·키 발급은 **직접** 해야 한다.

## 1. 로컬 실행

```bash
pnpm install
```
```bash
pnpm dev
```
```bash
pnpm test
```

`pnpm test`는 캘린더 표시 계산, KOPIS 파싱, DB 스키마(권한·탈퇴 범위)를 검사한다.

## 2. Supabase 프로젝트

1. supabase.com에서 프로젝트를 만든다. 지역은 Northeast Asia (Seoul).
2. 이 저장소를 프로젝트에 연결하고 마이그레이션을 올린다.
```bash
npx supabase login
```
```bash
npx supabase link --project-ref <프로젝트 ref>
```
```bash
npx supabase db push
```
3. Authentication > Sign In / Providers 설정
   - **Anonymous sign-ins: 켜기** (비회원)
   - Email: 켜기, Confirm email 켜기
   - Google·Apple·Kakao: 각 개발자 콘솔에서 클라이언트 ID·비밀값을 받아 입력한다.
     - Kakao: 이메일 동의 항목은 비즈 앱 전환이 필요할 수 있다.
     - Apple: iOS에서 소셜 로그인을 넣으면 필수다.
4. Authentication > URL Configuration > Redirect URLs에 아래 두 주소를 추가한다.
   - `https://<웹 도메인>/auth/callback`
   - `com.duckchinso.app://auth/callback` (앱)
5. 운영자 지정: SQL Editor에서 `insert into public.admins (user_id) values ('<운영자 auth.users id>');`

## 3. Edge Functions·정기 작업

```bash
npx supabase functions deploy delete-account
```
```bash
npx supabase functions deploy answer-inquiry
```
```bash
npx supabase functions deploy sync-concerts --no-verify-jwt
```
```bash
npx supabase functions deploy sync-artists --no-verify-jwt
```
```bash
npx supabase secrets set KOPIS_API_KEY=<키> RESEND_API_KEY=<키> MAIL_FROM="덕친소 <noreply@도메인>" MUSICBRAINZ_USER_AGENT="Duckchinso/0.1 ( 연락처 )"
```

- `sync-*` 함수는 직접 service role 키를 확인하므로 JWT 검증을 끈다.
- 정기 작업(`20261103000003_jobs.sql`)이 함수를 부르려면 SQL Editor에서 Vault에 두 값을 한 번 넣는다.
```sql
select vault.create_secret('https://<ref>.supabase.co', 'project_url');
select vault.create_secret('<service_role 키>', 'service_role_key');
```
- 첫 데이터는 손으로 한 번 실행한다. 아티스트를 먼저 받아야 공연과 대조할 수 있다.
```bash
curl -X POST -H "Authorization: Bearer <service_role 키>" https://<ref>.supabase.co/functions/v1/sync-artists
```
```bash
curl -X POST -H "Authorization: Bearer <service_role 키>" https://<ref>.supabase.co/functions/v1/sync-concerts
```
- 검수 대기 공연(`status = 'review'`)은 Supabase Studio에서 확인해 `published`로 바꾼다. 예매 오픈 일시(`ticket_open_at`)도 이때 입력한다.
- 문의 답변: 운영자 계정으로 `answer-inquiry` 함수를 호출한다(`{ inquiryId, answer }`). 관리자 화면은 2차.

## 4. 웹 배포 (Vercel)

1. Vercel에서 GitHub 저장소 `Yeojh3261/DUCKCHINSO_proj`를 가져온다. 설정은 `vercel.json`에 있다.
2. Environment Variables에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`를 넣는다. **anon 키만** 넣는다.
3. 배포 주소를 2-4의 Redirect URLs에 추가한다.

## 5. 앱 패키징

공통: 웹 코드를 바꿀 때마다 아래 명령으로 빌드해서 네이티브 프로젝트에 복사한다.

```bash
pnpm cap:sync
```

`.env`에 Supabase 값을 넣고 빌드해야 앱이 실제 백엔드를 쓴다.

**Android** (`android/`, minSdk 26 = Android 8.0, target 36)

- **JDK 21이 필요하다.** 지금 PC에는 Java 26만 있어 Gradle 8.14가 실행되지 않는다("Unsupported class file major version 70").
  - Android Studio를 설치하면 JDK 21이 함께 온다. `JAVA_HOME`을 그 경로로 바꾼다.
- Android Studio로 `android/` 폴더를 열고 Run. 또는 아래 명령으로 빌드한다.
```bash
npx cap open android
```
- 스토어 배포: Build > Generate Signed App Bundle(.aab). 서명 키는 커밋하지 않는다(`.gitignore`).

**iOS** (`ios/`, 최소 iOS 16, Swift Package Manager)

- Windows에서는 빌드할 수 없다. Codemagic(클라우드 macOS)이나 Mac + Xcode가 필요하다.
- Codemagic: 저장소를 연결하고 Capacitor 템플릿을 고른 뒤, 빌드 전 스크립트에 `pnpm install && pnpm cap:sync`를 넣는다. Apple Developer 계정의 인증서·프로비저닝을 연결한다.
- 사진 접근 문구(`NSPhotoLibraryUsageDescription`), 카메라 문구, 로그인 복귀 스킴(`com.duckchinso.app`)은 `Info.plist`에 넣어 두었다.

**앱 ID:** `com.duckchinso.app`은 임시값이다(기획서 미결 사항). 바꾸려면 다음 세 곳을 함께 바꾼다.

- `capacitor.config.ts`
- `src/lib/supabase.ts`의 `APP_SCHEME`
- 네이티브 설정: AndroidManifest의 intent-filter, Info.plist의 URL scheme

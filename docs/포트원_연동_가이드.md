# 포트원(PortOne) V2 연동 가이드 — 멤버십 웹 결제

작성 2026-11-18 · 대상: 운영자(직접 하는 작업) · 코드·보안 설계: `docs/결제_멤버십_연동_설계.md`
가격: **월 4,900원, 처음 구독하는 사람은 첫 달 990원** (마이그레이션 44에 들어 있음)

> 코드는 다 되어 있다. 이 문서는 **포트원 계정·키를 만들어 우리 서버에 넣는 일**과 **켜기 전 확인**만 다룬다.
> 순서를 지킨다: 테스트 채널로 스테이징에서 끝까지 확인 → 실 채널 계약 → 운영 키로 교체 → 판매 켜기.
> 포트원 콘솔 메뉴 이름은 개편될 수 있다. 화면이 다르면 같은 뜻의 메뉴를 찾는다 (공식 문서: developers.portone.io).

## 0. 무엇이 어디에 들어가나

| 값 | 어디서 받나 | 어디에 넣나 | 공개 여부 |
|---|---|---|---|
| 상점 ID (`store-…`) | 관리자 콘솔 › 결제 연동 › 연동 정보 | 앱 `VITE_PORTONE_STORE_ID` **그리고** 서버 `PORTONE_STORE_ID` | 공개값 |
| 채널 키 (`channel-key-…`) | 결제 연동 › 채널 관리 (결제 수단마다 하나) | 앱 `VITE_PORTONE_CHANNELS` | 공개값 |
| V2 API Secret | 결제 연동 › 연동 정보 › API Keys › V2 API Secret 발급 | 서버 `PORTONE_API_SECRET` | **비밀** |
| 웹훅 시크릿 | 결제 연동 › 웹훅 관리 (테스트·실연동 따로) | 서버 `PORTONE_WEBHOOK_SECRET` | **비밀** |
| 빌링키 암호화 키 | 우리가 만든다 (`openssl rand -base64 32`) | 서버 `BILLING_ENC_KEY` | **비밀** |

- **비밀값은 Supabase Edge Function 비밀값으로만** 넣는다.
  - `.env`의 `VITE_…`에 넣으면 앱 번들에 실려 누구나 볼 수 있다. 절대 안 된다.
  - git·채팅·스크린샷에도 남기지 않는다.
- 테스트용과 운영용 키·시크릿은 **서로 다른 값**이다. 스테이징 프로젝트에는 테스트 값만, 운영 프로젝트에는 운영 값만 넣는다.

## 1. 포트원 가입·상점 만들기

1. https://admin.portone.io 가입 (사업자 정보로).
2. 상점을 만들고 **V2**로 연동한다고 고른다. V1(아임포트)이 아니다.
3. 결제 연동 › 연동 정보에서 **상점 ID**를 복사한다.

## 2. 테스트 채널 만들기 (계약 없이 바로)

결제 연동 › 채널 관리 › **테스트** 탭 › 채널 추가. 결제 수단마다 정기결제(빌링)를 지원하는 PG를 고른다.

| 앱 결제 수단 | 채널 (예) | `VITE_PORTONE_CHANNELS` 이름 |
|---|---|---|
| 신용·체크카드 | 토스페이먼츠·KG이니시스·나이스페이 중 **정기결제(빌링)** 지원 PG | `card` |
| 카카오페이 | 카카오페이 (정기결제) | `kakaopay` |
| 네이버페이 | 네이버페이 (정기결제) | `naverpay` |
| 토스페이 | 토스페이 (정기결제) | `tosspay` |

- 채널마다 나오는 **채널 키**를 모은다.
- 카드 PG는 실 계약 때 수수료·정산 주기·구매자 정보 요구를 비교해서 고른다.
  - **카드는 KG이니시스로 확정 (2026-11-19).** 이니시스는 빌링키 발급 때 이름(필수)·휴대폰·이메일(PC 필수)과 offerPeriod(모바일 필수)를, 청구 때마다 이름·휴대폰·이메일을 요구한다. 앱은 카드를 고르면 구매자 정보를 받아 결제창에만 넘기고(`src/lib/buyer.ts`), 서버는 청구 때 포트원 빌링키 정보에서 다시 읽는다(`pg.ts` `buyerOf`). 덕친소 DB 에는 저장하지 않는다. 카드 채널 키는 `VITE_PORTONE_CHANNELS` 의 `card:` 에 이니시스 채널 키를 넣는다
- 처음엔 네 개를 다 열 필요 없다. 카드 + 카카오페이 두 개로 시작해도 된다. 앱은 환경값에 있는 수단만 보여 준다.

## 2-1. 나이스(나이스정보통신 V2) 채널로 연결할 때

포트원 V2에서 나이스는 **"나이스정보통신(신모듈)"** 채널 하나다 (나이스페이먼츠 계약도 이 채널. 계약 때 포트원에 확인).
근거: https://developers.portone.io/opi/ko/integration/pg/v2/nice-v2 (2026-11-18 확인)

### 연결 순서
1. 나이스와 **정기결제(빌링) + 간편결제(카카오페이·네이버페이 빌링)** 계약. 포트원 콘솔 › 채널 관리 › 실연동에서 나이스정보통신(신모듈)로 신청하면 포트원이 계약을 이어 준다.
   - 계약서에서 과세 방식이 **일반 과세(전액 과세)**인지 확인한다. 지정금액·복합과세면 부가세 금액을 따로 보내야 해서 코드 수정이 필요하다 (아래 표).
   - **부분 취소**를 쓰려면 같이 신청한다. 안 하면 전액 환불만 된다 (지금 운영자 화면은 전액 환불만 한다).
2. 채널 관리에서 나이스정보통신 채널을 추가하고 채널 키를 받는다. 테스트 탭에서 먼저 만들어 9장을 돌린다.
3. 앱 환경값: **나이스 채널 키는 `kakaopay`·`naverpay`에만** 넣는다.
   ```
   VITE_PORTONE_CHANNELS=kakaopay:<나이스 채널 키>,naverpay:<나이스 채널 키>
   ```
   - `card`에 나이스 채널을 넣지 않는다. 나이스는 **결제창으로 카드 빌링키를 발급하지 않는다** (카드 빌링키는 카드번호를 우리 서버가 받는 API 방식뿐 → 보안 부담이 커서 쓰지 않는다).
   - 카드 정기결제도 받고 싶으면 `card`에 결제창 카드 빌링키를 지원하는 **다른 PG 채널**(토스페이먼츠 등)을 따로 연다. 한 상점에 채널 여러 개를 둘 수 있고, 서버 코드는 PG와 상관없이 같다.
   - `tosspay`는 나이스 채널로 안 된다 (토스페이 채널이 따로 필요).
4. 서버 비밀값·웹훅·배포는 3~8장 그대로. 나이스라서 바꿀 서버 설정은 없다.

### 우리 설계에서 나이스 제약을 어떻게 맞췄나
| 나이스 제약 (포트원 문서) | 우리 쪽 처리 |
|---|---|
| 결제창 빌링키 발급은 간편결제(카카오페이·네이버페이)만, `billingKeyMethod: EASY_PAY` | 앱이 수단별로 이미 `EASY_PAY` + 제공사를 보낸다 (`src/lib/payment.ts`) |
| `issueId` 영문·숫자만, 40자 이내 | 결제창에는 UUID에서 하이픈을 뺀 32자를 보낸다. 서버(`pg-start`)에는 원래 값을 보내고, 빌링키 주인 확인은 `customer_token`으로 한다 |
| 결제창 제목(`issueName`) 40byte, `- % & + = [ ]` 등 금지, 괄호 비권장 | 상품 이름을 `덕친소 멤버십 월간`으로 (마이그 44) |
| 간편결제 빌링키 결제에 면세금액 필요 | 청구할 때 `taxFree: 0` (전액 과세)을 보낸다 (`_shared/pg.ts`) |
| 지정금액·복합과세 계약이면 부가세 금액 필수 | 일반 과세로 계약한다. 바뀌면 `payWithBillingKey`에 `vat` 추가 |
| 네이버페이 포인트(CHARGE)는 현금영수증 정보 필수 | 네이버페이는 카드(`availablePayMethods: ['CARD']`)만 받는다 |
| 네이버페이 빌링: 환금성 업종이면 이름·생년월일, 현금영수증 대상 가맹점이면 `cashReceipt` 필수 | 우리는 둘 다 아닌 것으로 본다. **계약 때 확인**: 해당되면 코드 수정 필요 |
| 부분 취소는 사전 계약 | 운영자 환불은 남은 금액 전액이 기본값 |
| 통화 KRW만 | 이미 KRW만 |
| **사파리 브라우저 미지원** | iOS 웹에서 결제창이 잘 안 될 수 있다. 9장에서 아이폰 사파리로 꼭 확인. 안 되면 결제 화면에 "다른 브라우저(크롬)로 열어 주세요" 안내를 넣는다 |

### 나이스로 바꿔도 그대로인 것
- 금액·기간은 DB가 정하고, 결제 결과는 서버가 포트원에 다시 조회해서만 반영한다.
- 청구 번호(`mbr_구독_회차_시도`)·웹훅 서명 확인·15분 갱신 cron·탈퇴 시 빌링키 삭제는 PG와 상관없다.
- 9장 확인 목록을 나이스 테스트 채널로 그대로 돌린다. 1번은 "카드" 대신 **카카오페이·네이버페이**로 한 번씩.

## 3. V2 API Secret 발급

1. 결제 연동 › 연동 정보 › API Keys › **V2 API Secret 발급**
2. 이름을 정한다 (예: `duckchinso-staging-server`). 창을 닫으면 다시 볼 수 없으니 바로 4장의 명령으로 넣는다.
3. 권한을 고를 수 있으면 결제 조회·빌링키 결제·결제 취소·빌링키 조회·삭제만 준다.

## 4. Supabase 비밀값 넣기 (스테이징 프로젝트)

```bash
supabase secrets set --project-ref <스테이징-ref> PORTONE_API_SECRET=<V2 API Secret> PORTONE_STORE_ID=<상점 ID>
```

```bash
supabase secrets set --project-ref <스테이징-ref> BILLING_ENC_KEY=$(openssl rand -base64 32) PORTONE_ALLOW_TEST=true
```

- `BILLING_ENC_KEY`는 한 번 정하면 **바꾸지 않는다.** 바꾸면 저장된 빌링키를 못 풀어 갱신 결제가 전부 실패한다. 교체 절차는 따로 만든다.
- 개인정보 키(`PII_ENC_KEY`)와 같은 값을 쓰지 않는다.
- `PORTONE_ALLOW_TEST=true`는 **스테이징에만** 넣는다. 운영에 있으면 테스트 카드로 진짜 멤버십을 얻을 수 있다.
- 웹훅 시크릿은 5장에서 받은 뒤 넣는다.

## 5. 웹훅 등록

1. 결제 연동 › 웹훅 관리 › **테스트** 탭
2. 웹훅 주소: `https://<스테이징-ref>.supabase.co/functions/v1/pg-webhook`
3. 버전은 최신(2024-04-25 이후 V2 형식)으로 둔다.
4. **웹훅 시크릿**을 복사해 넣는다:

```bash
supabase secrets set --project-ref <스테이징-ref> PORTONE_WEBHOOK_SECRET=<웹훅 시크릿>
```

- 우리 서버는 서명이 틀리거나 5분 넘은 알림은 401로 거절한다.
- 알림 내용을 그대로 믿지 않고 포트원에 다시 조회한다. 그래서 알림이 늦거나 빠져도 15분마다 도는 대사 작업이 맞춘다.

## 6. DB·서버 함수 배포 (스테이징)

1. 마이그레이션 적용 (43 멤버십 + 44 결제가 함께 올라간다):

```bash
pnpm db:push
```

   - 44에 `drop function public.my_membership()`이 있어 "위험한 변경"으로 표시되고 백업을 묻는다. **Y로 백업**한 뒤 진행한다.
     - 함수 모양을 바꾸려는 것이다. 데이터는 지우지 않는다.
2. 서버 함수 배포:

```bash
supabase functions deploy pg-checkout pg-start pg-renew pg-refund delete-account --project-ref <스테이징-ref> --use-api
```

```bash
supabase functions deploy pg-webhook --project-ref <스테이징-ref> --use-api --no-verify-jwt
```

   - `pg-webhook`만 `--no-verify-jwt`다. 포트원이 부르므로 로그인 토큰이 없고, 대신 서명 검증이 관문이다.
3. 15분 cron 확인: `select jobname, schedule from cron.job where jobname = 'duckchinso-pg-renew';`
   - 없으면 Vault에 `project_url`·`service_role_key`가 있는지 먼저 본다 (공연 수집 cron과 같은 값).

## 7. 앱 환경값 (스테이징 배포)

Vercel › 스테이징 › Settings › Environment Variables:

```
VITE_PORTONE_STORE_ID=store-…
VITE_PORTONE_CHANNELS=card:channel-key-…,kakaopay:channel-key-…,naverpay:channel-key-…,tosspay:channel-key-…
```

- 넣은 뒤 Redeploy.
- 결제창 주소는 사이트 보안 정책(CSP, `vercel.json`)에 넣어 두었다. 결제창이 안 뜨거나 빈 화면이면 브라우저 콘솔의 "Refused to frame/connect …" 주소를 알려 주세요. 그 도메인만 추가한다.

## 8. 판매 켜기 (스테이징)

DB(SQL Editor):

```sql
update public.membership_products set active = true where id = 'monthly';
```

- 가격은 이미 4,900원 / 첫 달 990원으로 들어 있다.
- 끄려면 `active = false`. 이미 구독 중인 사람의 갱신은 계속된다.

## 9. 스테이징 확인 목록 (테스트 채널, 실제 돈 안 나감)

PC 브라우저와 휴대폰 브라우저 **둘 다**. 휴대폰은 결제창이 페이지를 옮겼다가 `/membership?pg=return`으로 돌아온다.

| # | 할 일 | 기대 결과 |
|---|---|---|
| 1 | 멤버십 탭 › 카드 › 동의 체크 › 990원 결제 | 구독 중, 결제 수단 표시, 다음 결제일 = 한 달 뒤 같은 날, 다음 결제 금액 4,900원 |
| 2 | 동의 체크 없이 | 결제 버튼이 꺼져 있음 |

| 6 | 실패: 포트원 테스트 실패 카드 또는 콘솔에서 빌링키 삭제 후 5번 | "결제 실패" 표시, 혜택 유지, 다른 수단으로 다시 결제 가능 |

| 9 | 웹훅: 포트원 콘솔 "웹훅 테스트 전송" | 200. 시크릿을 일부러 틀리게 넣고 보내면 401 |
| 10 | 탈퇴 | 포트원 콘솔에서 그 빌링키가 삭제 상태 |
| 11 | DB 감사 기록 `select * from payment_events order by id desc limit 20` | 위 동작이 전부 남아 있음 |

## 10. 운영 전환

지금 상태 (2026-11-19): 스테이징 없이 **운영 프로젝트 하나**에서 테스트했다. 이니시스 테스트 채널(`INIBillTst`)로 990원 결제·빌링키 저장·웹훅 수신까지 확인. `PORTONE_ALLOW_TEST`는 지웠고, 상품은 꺼 둠(`active=false`), 테스트 구독(sandbox)은 자동결제를 끔.

1. **실 채널 계약.** 포트원 콘솔 › 채널 관리 › 실연동에서 KG이니시스 정기결제(빌링) 심사를 신청한다.
   - 심사에 사업자등록증, 서비스 화면(멤버십 결제 화면·환불 정책·이용약관)이 필요하다. 통신판매업은 간이과세자 신고 면제.
   - 승인되면 이니시스가 **실제 MID**와 signkey·INIAPI Key·IV를 준다. 이 값은 비밀이라 포트원 콘솔에만 넣는다.
2. **실 채널 만들기.** 실연동 탭에서 KG이니시스 V2 "결제창 일반/정기결제 · API 일반/정기결제" 채널을 실제 MID로 만든다. 과세구분 과세, 수동 승인 사용 안 함 (테스트와 같게).
3. **사이트 채널 키 교체.** Vercel `VITE_PORTONE_CHANNELS`를 `card:<실 채널 키>`로 바꾸고 Redeploy. 상점 ID(`VITE_PORTONE_STORE_ID`)는 그대로.
4. **웹훅.** 포트원 콘솔 웹훅 관리의 **실연동** 탭에도 같은 주소(`https://ynzktqolittllfgfifug.supabase.co/functions/v1/pg-webhook`)를 등록한다. 실연동 웹훅 시크릿이 테스트와 다르면 Supabase `PORTONE_WEBHOOK_SECRET`을 그 값으로 바꾼다.
5. **서버 비밀값.** `PORTONE_API_SECRET`·`PORTONE_STORE_ID`는 같은 상점이면 그대로. `BILLING_ENC_KEY`는 **바꾸지 않는다** (바꾸면 저장된 빌링키를 못 읽는다). `PORTONE_ALLOW_TEST`는 다시 넣지 않는다.
6. **판매 켜기.** `update public.membership_products set active = true where id = 'monthly';`
7. **실제 카드로 990원 한 번 결제 → 바로 운영자 환불(`pg-refund`)까지** 해서 실 채널 결제·취소를 확인한다.

## 12. 문제가 생기면

| 증상 | 볼 곳 |
|---|---|
| 결제창이 안 뜸 | 브라우저 콘솔 CSP 오류 (7장), `VITE_PORTONE_*` 값 |
| 결제는 됐는데 구독이 안 켜짐 | `pg_charges`의 그 청구가 `pending`이면 15분 뒤 대사가 처리. `failed`면 `fail_reason`을 본다 (`billing_key:other_customer` 등) |
| `billing_key:test_channel` | 운영에서 테스트 채널 키를 썼다. `VITE_PORTONE_CHANNELS`를 실 채널 키로 |
| `amount_mismatch` | 금액이 서버 값과 달라 자동 취소됨. 즉시 알려 주세요 (조작 시도이거나 설정 오류) |
| 갱신이 안 됨 | `cron.job_run_details`, `pg-renew` 함수 로그 |
| 웹훅 401 | 테스트/실연동 웹훅 시크릿이 바뀌었는지 |

# 덕친소 반응형 레이아웃 설계

작성일: 2026-11-05 (2026-11-06 결정 반영) · 기준: 디자인 기획안 v2(시뮬레이션 기준 390×844, "반응형은 이후 적용"), 현재 코드(`src/App.tsx` 앱 틀), iOS 프로젝트 설정

## 1. 지금 상태

- 모든 화면이 **폭 430px 한 줄**로 고정돼 있다. 데스크톱 웹에서는 가운데에 둥근 휴대폰 틀(`md:rounded-[40px]`)로 보인다.
- 아래 탭 바(캘린더·커뮤니티·채팅·MY), 좌우로 밀어 탭 이동, 화면 전환 슬라이드 애니메이션은 휴대폰 기준이다.
- iOS 프로젝트가 iPad도 지원하도록 설정돼 있었다(`TARGETED_DEVICE_FAMILY = "1,2"`). iPhone도 가로 회전이 허용돼 있었다. → 6장에서 iPhone 전용·세로 고정으로 바꿨다.

## 3. 기준 폭 (Tailwind 기본 단위 그대로)

| 구간 | 폭 | 틀 |
| --- | --- | --- |
| 기본 | 0~767px | 한 줄 + 아래 탭 바 |
| `md` | 768~1023px | 맨 위 앱 바(햄버거 ☰ · 덕친소 로고) + 본문 한 칸(최대 640px, 가운데) |
| `lg` | 1024px 이상 | 앱 바 + 목록 칸(380px) + 상세 칸(나머지, 최대 720px) |

## 4. 햄버거 서랍 메뉴 (`md` 이상)

```
┌──────────────────────────────────────────────┐
│ ☰  덕친소                                     │ ← 앱 바 (높이 56px, 항상 보임)
├──────────────────────────────────────────────┤
│        [각 화면의 헤더: 뒤로 · 제목 · 버튼]      │
│        [본문 / 목록·상세 두 칸]                 │
└──────────────────────────────────────────────┘

☰ 누르면 ↓
┌────────────┬─────────────────────────────────┐
│ 덕친소   ✕ │░░░░░░░░ (어둡게 덮음) ░░░░░░░░░░│
│ 📅 캘린더   │░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░│
│ 💬 커뮤니티 │░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░│
│ ✉ 채팅  (3) │░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░│
│ 👤 MY       │░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░│
└────────────┴─────────────────────────────────┘
```

- **왼쪽에서 열린다.** 각 화면 헤더의 뒤로 가기 버튼은 앱 바 아래에 그대로 있어 햄버거와 겹치지 않는다.
- 메뉴는 아래 탭 바와 같은 4개다. 안 읽은 채팅·덕친 요청 배지를 같이 보여 주고, 하나라도 있으면 ☰ 버튼에도 점을 찍는다.
- 지금 있는 탭을 강조한다. 메뉴를 누르거나 바깥을 누르거나 `Esc`를 누르면 닫힌다.
- 서랍 폭은 280px이다. 열리면 포커스가 서랍 안으로 가고, 닫히면 ☰ 버튼으로 돌아온다. `aria-expanded`와 `role="dialog"`를 쓴다.
- 휴대폰 폭(767px 이하)에서는 앱 바와 서랍이 없고 지금처럼 아래 탭 바를 쓴다.

## 5. 화면별 PC 배치

| 화면 | 기본 (휴대폰) | `md` | `lg` |
| --- | --- | --- | --- |
| 캘린더 | 달력 → 그날 공연 목록, 공연 누르면 상세로 이동 | 본문 640px | 왼쪽: 달력 + 공연 목록 / 오른쪽: 고른 공연 상세 |
| 커뮤니티 | 글 목록 → 글 상세로 이동 | 같음 | 왼쪽: 글 목록 / 오른쪽: 글 상세 |
| 채팅 | 대화방 목록 → 대화방으로 이동 | 같음 | 왼쪽: 대화방 목록 / 오른쪽: 대화방 |
| MY·설정 | 메뉴 목록 → 하위 화면 | 같음 | 같음 (한 칸, 최대 640px) |
| 로그인·동의 | 한 줄 | 가운데 카드(최대 440px) | 같음 |
| 운영자 | 한 줄 | 같음 | 신고·문의·검수: 목록 / 상세 두 칸 |
| 공개 문서 `/legal` | 이미 최대 720px | 같음 | 같음 |

**두 칸 동작 규칙**
- 주소는 지금과 같다(`/chats/:id`, `/community/post/:id`, `/concert/:id`). `lg`에서는 같은 주소가 목록 옆에 상세를 띄운다. 그래서 공유 링크와 푸시 알림 경로가 화면 폭과 상관없이 동작한다.
- 상세를 고르지 않은 상태(`/chats`)에서는 오른쪽 칸에 "대화방을 골라 주세요" 같은 빈 상태를 보여 준다.
- 두 칸일 때는 목록 ↔ 상세 사이의 슬라이드 애니메이션을 끈다(오른쪽 칸만 바뀐다).

## 6. 공통 부품 변경

| 부품 | 변경 |
| --- | --- |
| 앱 틀 (`App.tsx`) | 데스크톱 휴대폰 틀(둥근 테두리) 제거. 기본은 화면 꽉 채움, `md`부터 앱 바 + 서랍 |
| 아래 탭 바 (`BottomNav`) | `md`부터 숨김. 메뉴 정의(이름·경로·배지)는 서랍과 같이 쓴다 |
| 좌우 밀기 탭 이동 | 기본(휴대폰)에서만 |
| 바텀시트 (`Sheet`) | `md`부터 화면 가운데 대화상자(최대 440px) |
| 헤더 (`AppHeader`) | `lg` 두 칸에서 상세 칸의 뒤로 가기 버튼 숨김 |
| 토스트 | `md`부터 본문 칸 아래 가운데 |
| 글줄 길이 | 본문 글은 최대 640px. 그 이상 넓히지 않는다 |
| 누르는 영역 | 지금처럼 최소 44px. 마우스용으로 줄이지 않는다 |
| 마우스 | `md`부터 목록 줄에 hover 배경, 키보드 포커스 표시 유지 |

## 7. 앱 설정 (2026-11-06 적용)

- iOS: `TARGETED_DEVICE_FAMILY = "1"`(iPhone 전용), `UISupportedInterfaceOrientations`는 `Portrait`만.
- Android: `MainActivity`에 `android:screenOrientation="portrait"`. 단 targetSdk 36(Android 16)부터는 폭 600dp 이상 화면(태블릿·폴더블 펼침)에서 방향 고정이 무시된다. 그 경우는 3장의 `md`·`lg` 배치가 맡는다.
- 2차에서 iPad를 지원하면 `md`·`lg` 배치를 그대로 쓰고 `TARGETED_DEVICE_FAMILY`를 `"1,2"`로 되돌린다.

# 아이디·비밀번호 찾기 설계

작성일: 2026-11-11 · 대상: 아이디(이메일 가입) 회원. 카카오·네이버·구글·Apple 회원은 각 서비스 계정으로 로그인하므로 대상이 아니다(화면 안내 문구 있음).

## 1. 지금 상태 (코드 확인)

| 기능 | 화면 | 서버 | 메일 경로 | 상태 |
| --- | --- | --- | --- | --- |
| 아이디 찾기 | `FindAccount` "아이디 찾기" 탭 | Edge 함수 `login-id` `action: find` → `login_id_by_email()`로 찾아 아이디 복호화 | **Resend** (`RESEND_API_KEY`·`MAIL_FROM` 등록됨) | 동작 가능. 가입 여부를 화면에 알리지 않음, IP당 10분 5회 |
| 비밀번호 재설정 | `FindAccount` "비밀번호 재설정" 탭 → 메일 링크 → `AuthCallback ?next=password` → `/my/password` | Supabase Auth `resetPasswordForEmail` (캡차 토큰 포함) | **Supabase Auth 메일** | **확인 필요**: Auth 에 사용자 SMTP 를 연결하지 않았다면 기본 메일 서버는 프로젝트 팀원 주소로만 보내 일반 사용자에게 도착하지 않는다 |

두 기능이 서로 다른 메일 경로를 쓰는 것이 핵심 위험이다. 아이디 찾기는 되는데 비밀번호 재설정 메일만 안 오는 상황이 생긴다.

## 2. 설계 (최소 변경)

### 2-1. 비밀번호 재설정 메일을 Resend 로 (설정만, 코드 없음)

Supabase 대시보드 > Authentication > Emails > **SMTP Settings**:

| 항목 | 값 |
| --- | --- |
| Host / Port | `smtp.resend.com` / `465` |
| Username | `resend` |
| Password | Resend API 키 (함수 비밀값과 같은 키 또는 SMTP 전용 키) |
| Sender | `noreply@duckchinso.com` (Resend 에서 도메인 인증된 주소, `MAIL_FROM`과 같게) |

- 같은 화면의 **Rate Limits > Emails sent per hour** 를 사용자 규모에 맞게(예: 30) 올린다. 기본 SMTP 는 시간당 몇 통이다.
- **Email Templates > Reset Password** 를 한국어로: "덕친소 비밀번호 재설정 · 아래 버튼을 누르면 새 비밀번호를 정할 수 있어요. 직접 요청하지 않았다면 무시해 주세요." 링크는 `{{ .ConfirmationURL }}` 그대로.
- **URL Configuration > Redirect URLs** 에 `https://duckchinso.com/auth/callback*` 이 있는지 확인(앱 출시 때 L8 전환과 함께 앱 링크도 추가).

이렇게 하면 앱 코드 변경 없이 두 기능이 같은 발송 경로(Resend)를 쓴다.

### 2-2. 보안 규칙 (이미 지켜지는 것 + 추가)

| 규칙 | 아이디 찾기 | 비밀번호 재설정 |
| --- | --- | --- |
| 가입 여부 비노출 | ✅ 항상 "가입된 이메일이면 보냈어요" | ✅ Supabase 가 같은 응답 |
| 남용 방지 | ✅ IP당 10분 5회 (`login_attempts`) | ✅ Turnstile 캡차 + Auth 메일 발송 제한 |
| 메일 내용 | 아이디만, 비밀번호·링크 없음 | 1회용 링크(기본 1시간 만료) |
| 링크로 들어온 뒤 | — | 복구 세션은 비밀번호 변경 화면으로만 보낸다(`?next=password`). **추가 권장**: 비밀번호를 바꾸면 다른 기기 세션 종료 → `updateUser` 성공 뒤 `signOut({ scope: 'others' })` 한 줄 |
| 알림 | — | **추가 권장**: 비밀번호가 바뀌면 가입 메일로 "비밀번호가 변경됐어요, 본인이 아니면 문의" (Supabase Auth > Emails > *Password changed* 알림 켜기, 코드 없음) |
| 로그 | 아이디·이메일 원문은 남기지 않음(기존 원칙) | 같음 |

### 2-3. 하지 않는 것

- 휴대폰 본인인증으로 찾기: 전화번호를 받지 않는 서비스라 대상 정보가 없다.
- 이메일을 잊은 경우: 문의(운영팀)로만. 운영자는 가입 이메일을 화면에서 볼 수 없으므로(개인정보 비노출 원칙) 본인 확인 후 SQL Editor 로 처리한다 — 절차는 운영 문서에.
- 자체 구현 비밀번호 재설정(인증코드 방식): Supabase 기본 흐름이 같은 일을 하므로 SMTP 연결로 충분하다. Supabase 메일이 계속 문제면 그때 `login-id` 함수에 `reset_code`·`reset_verify` 동작을 추가(가입 때 쓰는 `email_codes`·시도 제한 재사용).
